# AGENTS GUIDE
- **Runtime**: Bun 1.x with ESM modules; run `bun install` before anything.
- **Dev Server**: `bun dev` serves the React UI with hot reloading.
- **Build**: `bun run build.ts`; CLI flags mirror `bun build` options.
- **Start**: `bun start` runs `src/index.tsx` in production mode.
- **Tests**: `bun test`; run single spec via `bun test docx/parse.test.ts` before PRs.
- **Linting**: No dedicated script; rely on strict TS, build, and tests for feedback.
- **Formatting**: Match existing two-space indents, double quotes, trailing semicolons.
- **Imports**: Always include `.ts/.tsx` extensions and prefer `import type` for types.
- **Aliases**: Use the `@/*` path alias instead of deep relatives when possible.
- **Types**: Embrace `strict` typing, avoid `any`, and narrow external data early.
- **Naming**: camelCase for vars/functions, PascalCase for React components and models.
- **State**: Keep React state immutable; push derived logic into helpers in `src/client/util`.
- **Data Access**: Interact with persistence via `src/stores`; reuse existing query helpers.
- **Error Handling**: Throw descriptive `Error`s and return typed `Response`s with status codes.
- **Async**: Prefer `async/await`; wrap OpenAI/Bun I/O in retries like `retryWithBackoff`.
- **Logging**: Use `console.log` for progress and `console.error` for failures only.
- **Bun APIs**: Use Bun helpers (`Bun.write`, `Bun.Glob`) alongside Node fs patterns already present.
- **Styling**: Tailwind utilities stay inline; keep class order consistent with nearby components.
- **Rules**: No Cursor/Copilot rule files detected; treat this guide as the authoritative policy.
